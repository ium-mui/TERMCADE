# 项目治理

[English](../../GOVERNANCE.md) · [한국어](../ko/GOVERNANCE.md) · [简体中文](GOVERNANCE.md)

TERMCADE 采用轻量的维护者主导治理模式，目标是决策透明、发布安全、贡献门槛低。

## 角色

**贡献者**是通过 Issue、代码、文档、翻译、评审、测试或社区帮助参与的任何人，可以提出变更并参与公开设计讨论。

**评审者**是在一个或多个领域证明了知识和可靠性的贡献者，可以分类 Issue 并提供正式评审；除非同时是维护者，否则不能合并或发布。

**维护者**拥有仓库写权限，负责范围决策、评审、合并、安全响应、发布、自动化和行为准则执行。维护者必须使用最小权限、启用强账户安全、披露利益冲突，并遵守与贡献者相同的保护分支规则。

## 角色变更

维护者可根据持续且建设性的参与、可靠的技术判断、可信评审和符合项目价值的行为，提名贡献者成为评审者或维护者。涉及个人信息的讨论可私下进行，但接受后的角色变更应公开记录。

任何人都可随时退出角色。长期不活跃、账户安全丧失、重复违反政策或无法安全履职时可移除维护权限。在隐私和安全允许时，项目记录变更及运营原因。

## 决策

日常变更通过 PR 评审决定。新的架构边界、不兼容存储格式、移除支持平台或语言、许可证及治理变更，都必须在实现前通过公开 Issue 或提案讨论。

项目追求 rough consensus：处理实质性反对意见，优先采用负责维护者和活跃贡献者都能支持的方案。合理期限内无法达成一致时，由维护者决定并记录理由、备选方案和异议。有重大利益冲突的维护者必须回避。

只有维护者可以合并发布 PR、管理 secrets、发布 advisory 或在紧急情况下绕过规则。发布遵循[发布流程](RELEASING.md)，绕过后必须审计。有其他合格维护者时，不应由一人独自批准并发布高风险安全或治理变更。

治理修改使用带 `governance` 标签的 PR，经过公开评审期和维护者批准，并说明动机与迁移影响。纯编辑修正使用普通文档流程。

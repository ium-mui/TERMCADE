# 보안 정책

[English](../../SECURITY.md) · [한국어](SECURITY.md) · [简体中文](../zh-CN/SECURITY.md)

## 지원 버전

최신 릴리스 minor 계열에 보안 수정을 제공합니다. 개발 snapshot과 이전 버전은 재현에 사용할 수 있지만 수정은 현재 `main`에서만 릴리스합니다.

| 버전 | 지원 |
| --- | --- |
| 최신 릴리스 | 예 |
| 이전 릴리스 | 아니요 |
| 릴리스 전 `main` | 가능한 범위에서 지원 |

## 취약점 신고

공개 이슈를 만들지 마세요. GitHub [비공개 취약점 신고](https://github.com/ium-mui/TERMCADE/security/advisories/new)에 다음을 포함합니다.

- 영향받는 버전, commit, 운영체제, 터미널
- 취약점 유형과 현실적인 영향
- 최소 재현 절차 또는 proof of concept
- 전제 조건과 신뢰할 수 없는 입력 필요 여부
- 알고 있다면 완화 방법
- 다른 곳에 공개했는지 여부

무관한 개인 데이터를 제거하고 소유하거나 평가 허가를 받은 시스템과 사용자만 대상으로 테스트합니다.

## 대응 절차

유지관리자는 완전한 신고를 7일 안에 확인하고 14일 안에 최초 평가를 제공하는 것을 목표로 하지만 보장하지는 않습니다. 영향 검증, 수정과 advisory 준비를 비공개로 진행하고 가능하면 신고자와 공개 날짜를 합의합니다.

접수된 수정은 비공개 fork 또는 제한 브랜치에서도 일반 리뷰와 CI 기준을 따릅니다. 보안 릴리스는 새 SemVer patch 이상으로 게시하며 기존 태그와 릴리스를 다시 쓰지 않습니다. 신고자가 원하지 않으면 익명으로 처리합니다.

로컬 게임 지갑 조작이 더 넓은 무결성 문제나 코드 실행으로 이어지지 않으면 일반적으로 보안 취약점이 아니라 버그로 분류합니다.

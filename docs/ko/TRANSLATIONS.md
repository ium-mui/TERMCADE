# 문서 및 번역 정책

[English](../TRANSLATIONS.md) · [한국어](TRANSLATIONS.md) · [简体中文](../zh-CN/TRANSLATIONS.md)

TERMCADE 문서의 기준 언어는 영어이며 현재 한국어(`ko`)와 중국어 간체(`zh-CN`)를 지원합니다. 기준 파일을 옮기지 않고 다른 로케일을 추가할 수 있는 구조입니다.

## 기준 파일 구조

```text
README.md                  영어 프로젝트 README
README.ko.md               한국어 프로젝트 README
README.zh-CN.md            중국어 간체 프로젝트 README
docs/<NAME>.md             영어 기준 문서
docs/ko/<NAME>.md          한국어 번역
docs/zh-CN/<NAME>.md       중국어 간체 번역
<COMMUNITY>.md             영어 기준 커뮤니티 정책
docs/<locale>/<COMMUNITY>.md  참고용 정책 번역
```

번역과 기준 문서가 다르면 영어가 우선합니다. 이 규칙은 모호함을 해결하기 위한 안전장치이며 오래된 번역을 방치해도 된다는 뜻이 아닙니다.

## 문서 갱신

1. 영어 원문을 먼저 수정해 동작, 명령 이름, 링크를 확정합니다.
2. 같은 PR에서 한국어와 중국어 간체 파일을 갱신합니다.
3. 제목, 코드, 식별자, 명령 출력, 표, 경고, 링크 대상을 보존합니다.
4. 설명은 자연스럽게 번역하되 Rust 이름, CLI subcommand, 키 이름, 경로, 버전 문자열은 번역하지 않습니다.
5. 모든 로케일 페이지 상단의 언어 링크를 갱신합니다.
6. `./scripts/check.sh`를 실행합니다. `scripts/check-docs.sh`는 빠진 로케일 파일을 거부합니다.

번역을 갱신할 수 없는 기여자는 `area: i18n` 후속 이슈를 열어 PR에 연결해야 합니다. 사용자 영향에 따라 유지관리자가 일시적 차이를 허용할지 결정합니다.

## 언어 추가

`ja`, `pt-BR` 같은 유효한 BCP 47 언어 태그를 사용합니다.

1. 로케일 코드, 언어 표기, 최초 번역자, 유지보수 계획을 정의하는 이슈를 엽니다.
2. `README.<locale>.md`를 추가합니다.
3. `scripts/check-docs.sh`에 나열된 모든 파일을 `docs/<locale>/`에 추가합니다.
4. 모든 README와 문서 언어 링크에 로케일을 추가합니다.
5. CI가 새 로케일을 요구하도록 `scripts/check-docs.sh`를 확장합니다.
6. 다른 번역이 아니라 최신 영어 기준 문서에서 번역합니다.
7. 해당 언어에 능숙한 사람과 기술 내용을 아는 유지관리자의 리뷰를 받습니다.

## 번역 스타일

- 의미와 확실성 수준을 보존하고 영어에 없는 약속을 추가하지 않습니다.
- 대상 커뮤니티에서 널리 쓰는 소프트웨어 용어를 선택합니다.
- 예시는 실행 가능하게 유지하고 코드 내부 문장 부호를 바꾸지 않습니다.
- 이해하기 쉬운 표현을 쓰고 성별을 전제하지 않습니다.
- 제품명 `TERMCADE`는 모든 문서에서 번역하지 않습니다.
- 향후 문서에 영향을 줄 용어 결정은 번역 PR에 기록합니다.

기계 번역은 초안으로 사용할 수 있지만 병합 전 사람이 기술 정확성, 자연스러움, 명령, 링크, 안전 관련 표현을 검토해야 합니다.
